# 22: Inbox shows no indication a folder was already imported, allowing silent duplicate albums

Status: ready-for-agent

**Category:** bug
**Source:** UX walkthrough session (Playwright MCP, browser-driven, per
ADR-0009), reported via `HANDOFF.md`. Reporter-suggested severity:
Critical.

## What was observed

`/api/inbox` (`beetsplug/webimport/server.py`, `api_inbox_list`) lists
every subdirectory of `inbox_dir` with no cross-reference to library or
Grace Period/undo state. Because this repo runs `copy: yes` (source files
legitimately remain in the inbox after a successful import — see
`CONTEXT.md`'s Grace Period entry), an already-imported folder still shows
an active "Start import" button with nothing distinguishing it from a
never-imported one.

Re-clicking "Start import" on an already-imported folder re-runs full
review from scratch. In testing, choosing "Use as-is" on the second pass
produced a **second, differently-tagged album** ("Lea Salonga – Mulan...")
alongside the first, correctly MusicBrainz-resolved one
("Jerry Goldsmith, Matthew Wilder & David Zippel – Mulan"), because
`duplicate_action: ask` / `get_duplicate_action` keys off albumartist and
the raw file tags didn't match the already-resolved album in the library
closely enough to trigger the duplicate-decision prompt at all.

## Why it matters

This is a real, silent data-integrity gap, not just a cosmetic one: a
second click can leave two albums in the library representing the same
physical files, with no prompt or warning at any point. It also
potentially touches the **Placement Conflict** concept already in
`CONTEXT.md` (the umbrella for "two things want the same library slot") —
worth deciding during triage/grilling whether re-importing an
already-imported folder should route through that same decision shape, or
needs its own resolution.

## Reproduction

1. Reset the disposable library (see `docs/agents/dev-environment.md`),
   start the server, import the Mulan test album fully (start import →
   force target MBID `a5483fb3-634b-4254-a966-de33cefd1f17` via search-by-ID
   → select → apply).
2. Return to the Inbox tab. The same folder is still listed with an active
   "Start import" button.
3. Click "Start import" again, click "Review", click "Use as-is" (skip the
   MBID override this time).
4. Check the Library tab: two albums now exist for the same underlying
   files.

## Agent Brief

**Category:** bug
**Summary:** Detect already-imported inbox folders via directory marker files (`.webimport_imported`) and surface dimmed [Imported] status with Re-import and Delete actions

**Current behavior:**
Because beets runs in `copy: yes` mode, source files remain in `.inbox/` after import. `/api/inbox` returns all subdirectories indiscriminately. Re-clicking "Start import" runs a full candidate review from scratch and can silently create duplicate albums in the library if candidate tags differ from raw tags.

**Desired behavior:**
1. **Backend marker file (ADR-0010):** When an import is successfully applied, the backend drops a `.webimport_imported` marker file containing `{ "album_id": <int>, "imported_at": "<iso_timestamp>", "staging_bin": <bool> }` inside the inbox folder.
2. **Scan & Detection:** `/api/inbox` inspects each folder and tags it with `imported: true` and its `album_id` if `.webimport_imported` is present.
3. **Grace Period & Undo integration:** If the import is undone within the Grace Period, the undo action deletes `.webimport_imported`, making the directory unimported again immediately.
4. **Staging Bins compatibility:** Staging Bins (`_grouped/<id>/bin_N/`) also receive the marker file on apply; when their Grace Period expires (ticket #13), the staging directory is cleaned up.
5. **UI Affordance:** Already-imported folders in the Inbox view:
   - Render with a dimmed styling and an `[Imported]` badge.
   - Replace the "Start import" button with a "Re-import" button (navigating/opening the reimport workflow for that `album_id`) and a "Delete from inbox" action (or dismiss).

**Key interfaces:**
- `server.py`: `_run_album_import` (apply completion hook writing marker), `api_inbox_list` (reading marker), `api_undo` (cleaning marker on undo), delete/clean inbox endpoint.
- `app.js`: `renderInbox` (rendering `[Imported]` badge and Re-import / Delete actions).
- `style.css`: `.inbox-item.imported` dimmed styling.

**Acceptance criteria:**
- [ ] Successfully applying an import writes `.webimport_imported` to the inbox folder.
- [ ] Already-imported folders are detected and rendered with an `[Imported]` badge and dimmed style.
- [ ] The "Start import" button on already-imported folders is replaced by "Re-import" and "Delete from inbox" actions.
- [ ] Clicking "Re-import" opens the reimport modal for that album.
- [ ] Undoing an import removes the marker file and restores the active "Start import" button.
- [ ] Staging Bins work consistently with the marker file and are cleaned up on grace period expiry per ticket #13.

**Out of scope:**
- Content-hashing all audio files on directory scan.
