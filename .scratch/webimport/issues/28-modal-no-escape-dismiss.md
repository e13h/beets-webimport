# 28: Modals have no visible close button and no Escape key handler

Status: ready-for-agent

**Category:** enhancement
**Source:** UX walkthrough session (Playwright MCP, browser-driven, per
ADR-0009). Reporter-suggested severity: Low.

## What was observed

Modals (`openModal()` in `static/app.js`) dismiss on backdrop-click, but
have no visible × button and no `Escape` key handler.

## Evidence

- `.playwright-mcp/09-album-detail.png` — the album detail modal, with no
  close affordance other than clicking the backdrop.

## Reproduction

1. Open any modal (e.g. an album detail view).
2. Note there is no × button; pressing `Escape` does not close it.

## Comments

> *This was generated by AI during triage.*

## Agent Brief

**Category:** enhancement
**Summary:** Add Escape key listener and visible close button to all UI modals

**Current behavior:**
Modals opened via `openModal()` in `app.js` only dismiss when clicking outside on the backdrop. There is no visible close ("×") button in the modal header, and pressing the `Escape` key has no effect.

**Desired behavior:**
1. Every modal includes a visible close ("×") button in the top right corner that dismisses the modal on click.
2. Pressing the `Escape` key on the keyboard closes the currently open modal.
3. Event listeners are properly cleaned up when the modal is closed to prevent listener accumulation.

**Key interfaces:**
- `app.js` (`openModal` function, modal container creation).
- `style.css` (`.modal-close-btn` positioning and hover styles).

**Acceptance criteria:**
- [ ] Pressing `Escape` closes any currently open modal.
- [ ] All modals (review candidate, duplicate review, album detail, reimport) render a visible close button.
- [ ] Clicking the close button dismisses the modal.
- [ ] Backdrop click-to-dismiss continues to work as before.

**Out of scope:**
- Redesigning modal layout or content beyond adding the close affordance.
