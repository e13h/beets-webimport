# 23: No success/failure feedback when applying a review decision

Status: ready-for-agent

**Category:** enhancement
**Source:** UX walkthrough session (Playwright MCP, browser-driven, per
ADR-0009). Reporter-suggested severity: High.

## What was observed

Submitting a review decision (forcing an MBID via search-by-ID, or the
final "Select" to apply) closes the review modal instantly, but the real
import work — copy, tag write, art fetch/embed, and the `album_imported`
event that registers the Grace Period/undo record (see
`docs/agents/dev-environment.md`'s "Timing/race facts" section) — keeps
running in the background for several seconds afterward. The UI gives no
indication that anything is still in progress, or that it succeeded/failed,
once the modal closes.

## Why it matters

The user has no way to tell "it's still working" from "it's done" from
"it silently failed," short of manually flipping to the Library or Undo
tab and checking whether the album has appeared yet.

## Evidence

- `.playwright-mcp/03-after-use-id.png` — modal gone immediately after
  submitting the forced MBID.
- `.playwright-mcp/05-after-select-apply.png` — modal gone immediately
  after submitting the final "Select," no toast/spinner/success message.

## Reproduction

1. Start an import review for any inbox album.
2. Submit an MBID override or a final "Select" to apply.
3. Observe: the modal closes immediately; the Library/Undo tabs don't yet
   reflect the result for several seconds afterward, with no in-UI signal
   that work is still happening.

## Agent Brief

**Category:** enhancement
**Summary:** Prototype candidate notification styles (toast vs banner vs status bar) for apply feedback, present options for user selection, and implement the chosen pattern

**Current behavior:**
When a review decision (such as forcing an MBID or clicking "Select" to apply a match) is submitted, the modal closes immediately. The background import pipeline (file copying, tag writing, art embedding, event firing) takes several seconds to complete, but the UI shows no indicator, leaving the user unsure if the action succeeded, failed, or is still running.

**Desired behavior:**
1. Prototype 3 distinct feedback affordances in the UI:
   - **Option A (Toast notification):** Floating non-blocking toast notification in a corner showing in-progress status, updating to success/error, auto-dismissing after completion.
   - **Option B (Top Banner):** Top-level header banner across the view displaying current import task activity.
   - **Option C (Status Bar / Footer):** Fixed bottom status bar showing active import tasks with completion badges.
2. Present the options to the user to choose their preferred interaction style.
3. Implement the chosen option cleanly with complete error and success handling.

**Key interfaces:**
- `app.js`: Review submission handlers (`openReview`, decision POST calls) and UI notification helper.
- Frontend status container in `index.html` and `style.css`.

**Acceptance criteria:**
- [ ] Prototypes of the feedback options are created and presented for user review.
- [ ] The user's selected feedback mechanism is implemented and active.
- [ ] Submitting an import decision immediately triggers the in-progress status.
- [ ] Completing the apply updates the notification to a success state with the imported album details and dismisses as designed.
- [ ] Any network or server error during decision POST is displayed clearly in the UI.
- [ ] No regressions to modal closing or inbox/library reloading behavior.

**Out of scope:**
- Modifying backend threading, `ApplyLock`, or beets pipeline stages.
